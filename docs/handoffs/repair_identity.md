# Identity, custody routing and authorization revisions

Implemented A01/A07/A10. Owned files: `server.mjs`, `customer-access.mjs`, `edit-revisions.mjs`, `authorizations.mjs`, new `job-policy.mjs`, and `test/job-policy.test.mjs`. Finance integrated the shared guards in POS routes; stock owns official checkout and `date_closed`.

- Customer/unit reassignment is limited to untouched Intake records. Links, documents, quoted lines, payments (including pending), custody and operational history block reassignment. Allowed corrections retain before/after identity in the audit transaction. Directory corrections preserve protected job snapshots; finance covered that integration.
- Portal links retain an identity fingerprint. An SQLite trigger revokes access in the same identity-update transaction; lookup independently checks the fingerprint. **Upgrade deliberately revokes unbound legacy links** because the original recipient cannot be inferred safely. Staff must issue new links. No retained documents/history are deleted.
- General/POS stage edits and progress updates reject Picked Up/Closed with instructions to use official vehicle checkout. Reopening completed jobs is blocked through generic edits, Ready, new approval requests and late customer signatures. Diagnosing remains available without repair authorization.
- Both approval creation aliases enforce the same revision. Added invoice/invoices/DocuSign revision targets for invoice agent; server defers those guards to handlers so idempotent invoice replays remain valid.
- QuickBooks imports default disabled. Explicit `QBPOS_IMPORT_MODE=insert-only` allows reviewed migration inserts; exact raw-payload retries return duplicates, changed existing records are rejected, totals/balance must reconcile, and each rejected bulk item rolls back independently. This intentionally retires destructive synchronization; do not enable it as an ongoing sync writer.
- Wired management route notification callback requested by comms; the closure runs after notification service initialization.
