# Scheduled arrivals and preparation — 2026-11-07

- `/calendar-arrivals.html` shows saved scheduled appointments for a chosen Phoenix calendar date, with Today/Tomorrow controls. It reports local/Google sync truth and physical custody separately. No provider calls or Google event import are performed.
- `src/calendar-intake.mjs` supplies desk-role-only `GET /api/shop/calendar-arrivals?date=YYYY-MM-DD`, `GET /api/shop/schedule/:id/intake-context`, and `POST /api/shop/schedule/:id/intake-job` (`{workOrderId,customerId,vehicleId}`). Existing-job preparation validates exact active customer/vehicle/open job; an immutable audited mapping makes identical retries harmless and rejects a different repair.
- `createAppointmentJob(db,user,id,body,createFn)` wraps the normal create-repair callback in one transaction (nested savepoint supported). The repair, ordinary creation side effects, and appointment mapping commit together. Exact material-payload replay returns the saved repair; conflicting intake, cancellation, ownership changes, or an existing different lot job cannot create or rebind another repair.
- `/intake.html?appointmentId=N` loads authoritative appointment context, locks the appointed customer and any appointed vehicle, prefills the complaint, and preserves unfinished/unknown-result drafts. The create request carries `appointment_id`. Before creating, intake rechecks the appointment; the backend enforces ownership under its write lock. Unknown creation/link responses still require saved-record review, with no automatic replay.
- Preparation never writes custody. Completion links to `/vehicle-checkin.html?workOrderId=N&appointmentId=N` when the vehicle arrives. Existing custody for another job directs staff to that job; normal create guards belong to root integration.
- Older HIN-only unfinished intake drafts migrate the identifier to the VIN input without discarding it or sending a HIN field. Vehicle form, roster, and phone check-in details are documented in their own handoffs.

Verification: 13 focused calendar tests and 25 focused intake tests passed under supported Node 22. The disposable real-server `browser-arrivals.py` journey passed Phoenix date boundaries, appointment with no initial vehicle, category/VIN entry, atomic `appointment_id` creation/replay, preparation without custody, and existing exact-job linking/retry. All fixtures are fictional; no review/live-provider mutation was used.
